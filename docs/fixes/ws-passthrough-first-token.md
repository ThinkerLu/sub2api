# WebSocket 透传的多轮首字延迟修复

同一 Responses WebSocket 透传连接持续进行多轮生成时，上游的文本、推理摘要和工具参数输出事件可以不带 `response_id`。旧逻辑仅在整个连接首次收到输出时更新活动轮次的首字时间，导致后续轮次虽然正常输出并记录用量，`first_token_ms` 仍为空。

修复先按响应 ID 或当前活动轮次确定输出归属，再独立记录该轮的首次输出时间。连接级首字时间仍只记录一次。没有语义输出的预热或空响应继续保持空值，不用总耗时代替首字延迟。

变更仅涉及计时，不修改转发帧、用量、账号调度、WebSocket 模式或数据库迁移；保留 `a510ccec3` 及其前置提交的 OOM 修复，不增加请求正文解析或复制。

回归测试覆盖真实 Relay 入口的空预热加连续三轮生成，以及文本、推理摘要、工具参数的 delta/done 事件。另以固定时钟验证有/无响应 ID 时各轮分别计时、重复输出不重写首次时间、连接级首次时间保持不变。

这里的首字延迟沿用既有口径：sub2api 观察到的首个输出事件，包括推理或工具参数事件，不一定等于桌面应用首次显示回答文字的时间。历史已缺失的数据不会自动补回。
